Graph layout for ontologies

Tidy Stress and Mycelium

Two layouts that draw ontology diagrams with far fewer crossed links and far fewer links running through classes than the widely used open-source layouts, plus Best Read, which picks the better of the two for each model.

An ontology diagram is only useful if a reader can follow each link from one class to another. Two things make that hard: links that cross, and links that pass under a class box, so that two unrelated classes look connected. General-purpose layouts usually reduce the first only as a side effect, and do little about the second. Tidy Stress and Mycelium are built to minimise both, without letting the drawing sprawl.

Below, a 179-class banking model: eleven taxonomies joined by relationships. On the left is the open-source layout that scored best on this model; on the right, ours. Mark problems shows every crossing (dot) and every link that runs through a class (red).

Honest scope: the benchmark, its models and its readability score are ours, and no study with people reading the diagrams has been done yet. The crossing and through-class counts are standard measures and tell the same story as the score. The full method and every limit are set out below under Limits.

What they are

Tidy Stress up to a few dozen classes

Places classes so that straight-line distances match how many links apart they are (stress majorization), then tidies the drawing with local moves that remove crossings, links through boxes and needlessly long links. No move is kept if it makes any of those worse. It tries a few variants and keeps the most readable.

Mycelium large and hub-heavy models

Draws groups of closely linked classes as compact pods joined by longer threads. It gives every hub a ring wide enough for all its neighbours, and fans classes with a single link out around the class they hang from, with room for the link's label.

Best Read a selector, not a layout

Runs the variants of Tidy Stress and Mycelium that suit the model's size within a time budget, scores each on readability, and keeps the best. It adds no layout step of its own.

Tidy Stress on a typical model

Most ontologies people draw have 10 to 30 classes. There the open-source layouts are already decent, and the difference is in the details: fewer crossings, no link through a class, links of even length.

Mycelium on the hardest case: hubs

A 53-class clinical record in which three classes link to almost everything. No placement can untangle this fully; Mycelium gives each hub a ring of room so its links stop running through other classes, at the cost of a larger drawing.

What is new, and what it builds on

Both layouts are assembled from published techniques, and this work depends on them. What is new is the design of the parts below, the order in which they run, and the measurement that chose each setting. No individual building block is claimed as new.

  1. Safe tidy-up passes. After stress placement, four local searches run in a tested order, each refusing any move that adds a crossing, a link through a box or an overlap:
    1. Swap two classes, or move one beside a neighbour, when that reduces crossings.
    2. Move a class off links that run through it.
    3. Pull classes toward their neighbours to shorten long links, then shrink the drawing evenly as far as the boxes allow.
    4. Move classes off links once more.
    Plain stress majorization (as in Graphviz neato) leaves typically 2–3× as many links through classes and about twice as many crossings.
  2. Hub rings (Mycelium). A link at a class with k neighbours gets an ideal length of at least Σ(neighbour width + 20 px) / 2π, the radius of a ring that holds those neighbours side by side. On the clinical-record model this rule alone cuts links through classes from about 80 to about 43.
  3. Pods (Mycelium). Links inside a group found by Louvain community detection are drawn at 0.85× the base length, links between groups at 1.6×. Stress placement then separates the groups without hard constraints, so a class shared by two groups can still sit between them.
  4. Leaf fanning with label room. Classes with a single neighbour are laid out last.
    • Each is placed around its neighbour by searching 48 directions at the nearest free distances.
    • The search minimises 100 × crossings + 80 × links touching the box + distance.
    • Each keeps max(40 px, label width + 16 px) from its neighbour, so the link's text fits.
    • A final pass re-places any whose link ended up crossed or touched.
    Ontologies are full of leaf subclasses, so this matters.
  5. A readability score that resists sprawl. Best Read scores on:
    • crossings (×10);
    • links through boxes (×8);
    • near-touching link pairs (×2);
    • overlapping boxes (×40);
    • mean link length;
    • area beyond eight times that of the boxes;
    • links longer than 1.8 × the median length.
    Without the last two terms, a score built on crossings favours drawings that avoid them by spreading out enormously.

How they run

boxes  := each class box + 16 × 12 px margin
leaves := classes with exactly one distinct neighbour, whose neighbour has others
core   := all classes − leaves
for each core link (u, v):
    len := L   (170 px; subclass links 0.9 L; Mycelium uses L = 260 px from 100 classes)
    Mycelium:  len := max(len, min(3 L, ring(u), ring(v)))      ring(x) = Σ(neighbour width + 20) / 2π
               len *= 0.85 inside a Louvain group, 1.6 between groups
    labelled link: len := max(len, (w_u + w_v)/2 + label width + 24)
D := all-pairs shortest-path lengths (Dijkstra)
place:  pivot-MDS start (+ random restarts while time allows) → stress majorization on D → push overlapping boxes apart
tidy:   fewer crossings → off links → shorten and shrink → off links   (each step time-boxed)
leaves: fan out round their neighbour → tidy once more → re-place any that are crossed or touched

Tidy Stress tries up to four variants within 1.5 s and keeps the best by the score:

  • plain stress with random starts;
  • pivot-MDS start with a final leaf improvement;
  • hub rings with leaf fanning;
  • leaf fanning alone.

Above 60 classes it runs only the second, because sharing the time starves each variant's tidy-up.

Mycelium needs at least 8 classes and has a 1 s budget.

Benchmark method

Models. 19 shapes:

  • Ontologies written from the published structure of PROV-O, SOSA/SSN, W3C ORG, the Pizza tutorial ontology and a FIBO-like loan model.
  • Models of typical domains: university, hotel booking, HR, clinical trial, telecom network, supply chain, customer 360, schema.org-style core types, a clinical record with three super-hubs, a 115-class biomedical taxonomy and a 179-class bank.
  • A 400-node scale-free graph, and three banks joined (537 classes).

Boxes. Sized from the label length.

Contenders. Graphviz neato, fdp and sfdp (with Graphviz's own overlap removal), ELK stress, force and layered, WebCola, d3-force, dagre, and Cytoscape cose and fcose, with sensible general settings rather than per-model tuning.

Fairness. Every layout received the same boxes, the same 170 px target link length where it takes one, and the same overlap removal afterwards.

Runs. Two seeds each, all in one browser tab on one machine, so times compare with each other but are not absolute. The drawings on this page are the first run of each.

Limits

  • Our measures, our score. The readability score is ours, and the layouts were tuned against it. The crossing and through-class counts are standard measures and agree with it, but no study with people reading the diagrams has been done.
  • Contender settings. The open-source layouts ran with general settings. Each could probably do better if tuned for these models, as ours were tuned for ontologies.
  • Models. They are reconstructions and inventions of typical shapes, not a public corpus of real ontologies. Commercial engines (yFiles, Tom Sawyer) were not tested.
  • Largest sizes. At around 500 classes, WebCola draws fewer crossings when given minutes to run. Within a budget of a second or two, Mycelium is the stronger choice.
  • Hub-heavy models stay hard. On the clinical-record model, a 20-second exhaustive search reaches only about 150 crossings against Mycelium's 161 in one second. Further big gains need a different kind of drawing, such as bundled links or repeating a hub, not a better placement.

What did not work

  • Stretching the drawing around a class until every single-link neighbour has a clean spot. Unlimited, it produced drawings millions of pixels wide on hub-heavy models; capped at 2.5×, it doubled the area for little gain.
  • Pulling hubs toward the centre. No gain.
  • Other stress weights and link lengths. 1/d weights in place of 1/d², and link lengths scaled by degree or by shared neighbours. No gain.
  • Alternatives to plain Louvain pods:
    • overlapping membership (a class also joins any group holding 30 % of its links);
    • coarser and finer resolutions.
    Each won on some models and lost on others, with no gain on average. The pods only bias link lengths, so having groups matters more than how they are drawn. Removing them costs most on large models: on the bank model, crossings rise from 73 to 128 and links through classes from 53 to 103.
  • Sharing a fixed time budget among several variants on large models. It starves each variant's tidy-up, and one variant with all the time does better.

Using the code

The reference implementation is plain JavaScript with no dependencies, about 500 lines. It takes box sizes [{w, h}] and links [[i, j, weight, labelWidth?]] (weight 2 for subclass links) and returns box centres [{x, y}].
